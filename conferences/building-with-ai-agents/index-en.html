How to run it yourself

Six ingredients for agentic engineering.

Agentic engineering, not vibe coding

~$2,000 of tokens across the sprint — about $9 per merged PR. That's the cheap part. The real question is when you pay for the code.

🎲 Vibe coding — low up front

  • No specs, no harness: you start shipping immediately
  • You pay in retry loops, and again six months later reverse-engineering code nobody understands
  • That's the maintenance tax — invisible on day one

🏗️ Agentic engineering — pay first

  • Specs, tests and CI cost you real days before the first agent runs
  • They're what makes the tokens land first time, not on the fourth attempt
  • The harness is cheap to write and expensive to skip
12 weeks and 552 more merged PRs later, the maintenance tax still hasn't come due. That's the harness paying back its up-front cost.

🧨 Why the multiplier was so large

This codebase is unusually well-suited to AI, for three reasons. Not every project gets 17–23×.

🔁 Massive repetition

~40 structurally similar panels an agent clones cheaply. By hand, that's the most expensive part.

🔌 Broad-but-shallow

Many Spring subsystems, each shallow. By hand, the cost is mostly looking things up, exactly what the agent absorbs.

🛡️ Strong guardrails

Multi-module CI, CodeQL, e2e and explicit instructions let the human safely accept high throughput.
🚀 Net effect: a ~6.5–8.5 month solo effort, compressed into ~11 days and ~2 weeks of human attention. The biggest leverage is on large-surface, pattern-heavy, well-tested code, not hard algorithms.

⚠️ Watch out for

Scope creep

"Build the whole thing" makes an agent wander.
Fix: one tight goal per task.

No tests, no trust

You can't read every line of 223 PRs.
Fix: harness first, green build before merge.

Giant PRs & review fatigue

A 2,000-line PR is impossible to review well.
Fix: small, reviewable chunks; pace yourself.

Wrong model

A weak model fails the hard tasks; a strong one is slow and costly.
Fix: match the model to the job.
Most failed runs aren't the agent's fault. They're a briefing problem.

♻️ How the token cache works

The model can reuse the processing of an identical prompt prefix — the unchanged beginning of its input. It still processes new input and generates a new answer.

What changes?Effect on cache reuse
Append a message or tool resultThe unchanged prefix can still hit; the new suffix needs processing.
Switch the modelThe old model's cached computation cannot transfer to the new one.
Edit AGENTS.md or instructionsOnce reloaded into the prompt, changed content breaks the match from that point onward.
Change tools or compact historyIf the rendered prefix changes, later cached context no longer matches.
Wait too long / cache is evictedEven identical input can miss. Retention and routing depend on the provider.
A cache miss is not necessarily a full reset.
An earlier, unchanged prefix may still be reusable.

OpenAI prompt caching · Claude prompt caching · mechanics vary by model and integration.

Prompt caching saves intermediate model computation, such as attention key/value states, rather than replaying a previous answer. Reuse requires a matching eligible prefix and an available cache entry; providers impose minimum lengths, breakpoints, lifetimes and routing constraints. Switching models cannot transfer the old model's state, but the selected model could already have its own matching cache. Changing a file on disk does not directly flush a provider cache: it matters only when the client rereads that file and changes the model's input. If AGENTS.md is replaced near the beginning, much of the later prefix may lose reuse. If the update is appended as a new message, the old prefix can remain reusable. The exact placement and refresh behavior are client-specific, not a documented universal Copilot guarantee. Tool schemas, their ordering, relevant settings and compaction can also change the rendered prefix. A miss does not imply deletion of the old entry. Correct instructions take priority over preserving cache hits; make necessary edits, avoid needless churn, and do not assume any one provider's TTL applies to all Copilot models.

Auto model selection · CLI routing and billing · 7 September 2026.

Task-optimized Auto is available in CLI, the Copilot app, cloud agent, GitHub web chat and VS Code. Some other IDEs use availability/reliability optimization instead. Cache-aware routing refers to choosing routing points that preserve useful prefix reuse, not changing the model midway through a call or constantly switching models. GitHub documents routing along natural cache boundaries but does not specify the exact conditions for rerouting an existing conversation. If a later call uses a different model, that model cannot reuse the previous model's cached computation. The 10% discount compares against the same selected model, not whatever model you would otherwise have chosen. Legacy annual request-based plans apply it to the multiplier instead of token credits. Model pools can change.
